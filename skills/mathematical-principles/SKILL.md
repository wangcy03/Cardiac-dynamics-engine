# 可维护的数理原理文档

把“系统为什么这样变化”说明白，并让读者能追溯到实现和真实证据。
正文是解释的维护源；证据区是已有产物的可重复投影，两者分别维护。
先读 `references/workflow.md` 的推导与影响映射；不要把当前项目的单位和阈值带到另一个领域。

## 1. 确定本次模式与范围

从用户请求和已有授权选择模式，常规细节自主决定：

| 模式 | 交付 | 边界 |
|---|---|---|
| `create` | 正式 HTML、维护约定、必要的有界证据适配器 | 从项目事实建立初稿，不先发明模型 |
| `update` | 本次变更影响的正文、公式、图表和证据 | 保留人工解释及历史失败，避免整篇重写 |
| `check` | 不改输入的结构、来源与陈旧性报告 | 区分静态检查、身份核查和实际验证 |

用户说“更新数理文档”即可执行 `update`；说“审计”或“只检查”时保持只读。
仅在缺少的决定会改变用途、基本方程、架构或证据解释时，说明具体影响后澄清。
不为已定文档样式、既有路径或可逆的实现选择反复确认。

## 2. 接续项目事实

1. 读项目入口、AGENTS、状态、规格、ADR、当前实现、既有文档与证据清单。
2. 先辨认人工正文、自动区域、派生图和归档，遵守现有文件责任。
3. 若已有证据刷新器和 freshness 检查，优先复用，先读它实际验证的范围。
4. 核对实际产物的路径、命令、退出码、配置、时间、单位和来源身份。
5. 只有当前项目确为本技能起源的心脏引擎时，读 `references/heart-engine.md`。

不要仅凭文件名猜物理含义；例如空间剖面和时间轨迹不能互换。
项目已有模型、图表、失败报告和试验记录应接续使用，不重复构造一套解释来源。

## 3. 建立变更影响映射

在工作记录中列出本轮变化及其影响，规模小可用几行文字：

| 变化 | 检查对象 | 应更新位置 |
|---|---|---|
| 状态、守恒或本构 | 量纲、符号、适用域、储能/耗散 | 推导、符号表、代码映射、限制 |
| 数值方法 | 重建、阶段时刻、权重、稳定约束 | 方法与失败判据、收敛证据 |
| 边界或耦合 | 交换量、流向、守恒、原子失败 | 控制体图、接口与账本 |
| 事件或时钟 | 真值、检测、交付、命令、动作 | 时序图、定义、缺失语义 |
| 运行数据或配置 | 时间窗、单位、来源、可比性 | 自动证据、实际图、身份表 |
| 只改排版 | 链接、公式显示、可读性 | 静态和可用浏览器检查 |

映射决定需要读什么和验证什么，避免更新结果数字却保留过时推导。
文档刷新本身不默认重跑昂贵求解；沿用已完成且身份可核查的记录。
若模型已变而没有对应运行，清楚显示陈旧/缺失，并按项目门安排必要验证。

## 4. 从第一性原理组织正文

按因果顺序写作，先用直白语言说明物理机制，再引入式子：

1. **用途与范围**：系统要回答什么，当前能运行什么，最终路线和未完成部分。
2. **系统边界**：控制体、状态、输入输出、初值和边界条件。
3. **基本定律**：守恒、平衡、动量或能量；说明内部交换为何抵消。
4. **闭合关系**：材料、本构、阻力、源项、参数来源及简化假设。
5. **连续到离散**：空间/时间离散、阶段边界、实际加权通量、源项与稳定约束。
6. **事件与信息**：物理事件、观测、交付和执行的顺序，实时接口可见什么。
7. **实现映射**：方程、状态、单位、代码模块/符号、失败行为和覆盖证据。
8. **真实结果与限制**：误差、极值、失败、缺失、比较条件和下一步。

每条核心方程回答：量是什么、单位是什么、正方向如何定、从哪里来、何时失效。
区分基本定律、经验闭合与工程假设；参数来自代码不等于参数已校准。
说明不变量、耗散或外部功的账本；未实现完整能量核验时保留缺口。
不把数值截断、clipping 或状态重置写成物理机制来掩盖失败。
缺失事件保持缺失，不凭固定延迟补出“真值”。

## 5. 创建或局部更新 HTML

新建时复制 `assets/principles-template.html` 到项目约定位置，再替换占位内容。
模板的通用守恒式只是写作示例；需以项目已确认的方程替换，不能当作实现事实。
已有正式文档按原结构局部修改，保留手工解释、章节锚点和历史证据链接。

- 默认浅色、本机字体回退、可键盘导航、窄屏局部横向滚动。
- 公式用原生 MathML，并包含非空 `annotation encoding="application/x-tex"`。
- 每组公式旁保留可展开的 LaTeX 源，MathML 与源在同次改动中维护。
- 新建可用 `div.equation` 或 `div.formula` 包住公式及 `details/pre`；既有公式紧邻后置源码的兄弟结构也可保留。
- 只用本地或内联资源；不依赖公式 CDN、网络字体、远程脚本。
- 学术引用可保留普通外部导航链接，离线时正文仍完整可读。
- 新建使用 `PRINCIPLES_EVIDENCE_START/END` 唯一注释对；更新沿用项目已有自动区域和刷新器契约，不强制迁移标记。
- 新文档使用 `PRINCIPLES_NARRATIVE_START/END` 标记人工正文；不强制改造旧文档。

自动刷新只替换证据区，不自动改任务状态、正文结论、用途或验收阈值。
不要在文档内增加另一套求解器，以免展示结果与真实核心分叉。

## 6. 图表与实际可视化

框架、时序、控制体或状态图按问题选择，图的数目不设硬编码门槛。
先从实际模块和因果路径提炼内容，再使用项目约定的 diagram-design 等技能。
遵守其首次样式选择流程；已有样式授权继续有效，不重复询问。
每幅内联 SVG 使用 `role="img"`、非空 `title`/`desc` 和可解析的 `aria-labelledby`。
配文字说明图表达什么、当前与规划的区别；箭头的量和方向要明确。

真实曲线、误差与收敛图使用标准科学绘图工具，输出独立 SVG/PNG 和输入身份。
从真实导出取值，保留单位、原始时间/位置轴、观察范围和预处理声明。
不生成“更漂亮”的假物理曲线，不平移对齐、平滑或重拟合来掩盖差异。
若项目已有固定观察器，链接或嵌入其真实产物；不每次重写观察器。
教学示意必须显著标明其性质，不用它充当本轮运行的测试 oracle。

## 7. 证据适配与身份

已有项目适配器：读明其输入字段、派生指标、缺失/异常行为和写入边界后复用。
新项目：按 `references/workflow.md` 建立小型、字段明确的有界适配器。
不要写一个猜测所有 JSON 数字含义的“万能解释器”。

对每项结论至少保留：

- 原始文件相对路径、字节 SHA-256、生成命令/退出码和记录的环境。
- 运行配置、初态、网格/步长、观察窗、比较对象与适用域。
- 指标定义、单位、参考来源、缺失字段和失败项。
- **历史运行记录的源身份**与**本次读取的源身份**分别展示。

当前读到的源码哈希只能证明读到了这份代码；不能补写为历史运行身份。
运行身份缺失时记录 `NOT_RECORDED`，无法匹配时记录不同，不伪造对应关系。
源文件、CSV、结果、日志可各有独立身份；一个摘要的 PASS 不替代完整性检查。
历史方案的失败、振铃、过冲和中止原因继续可查，不被新方案的通过覆盖。
`null`、缺失、非有限值和零不是同一个含义；不要把缺值默认成零或 PASS。
比较前确认单位、轴、输入/初态/边界和实际时间窗相容，否则展示不可比原因。

## 8. 检查与交付

先运行项目原有证据 freshness 检查，再执行本技能静态检查器：

```text
python <skill-dir>/scripts/check_document.py --root <project-root> --document <document-path> --output <report.json>
```

`--document` 和 `--output` 的相对路径均相对于 `--root`；根目录须涵盖文档及本地依赖。
检查器只读 HTML/本地资源，除显式指定的 JSON 报告外不写文件、不联网、不求解。
它检查本地链接/锚点、重复 ID、MathML XML/LaTeX 源、SVG 可访问性与离线静态依赖。
它拒绝可执行脚本、事件处理器、活动嵌入、远程资源和 CSS import；引用链接可以外部导航。
检查报告中的 `PASS_STATIC_ONLY` 只表示这些规则通过，不表示公式正确或结果成立。

在被允许的浏览器环境实际查看长文、公式、图、导航和观察器链接，并检查窄屏。
若工具明确拒绝某协议/来源并禁止绕过，停止相关尝试；不改用本地服务、代理或另一入口绕过。
将浏览器未运行的原因如实记录为 `NOT_RUN`；静态检查不能替代渲染。
按变更范围执行项目要求的测试/数值门；纯文档更新不擅自改变模型参数。
软件测试、数值收敛、外部数值参考、物理实验与临床验证分别报告。

交付说明写明：改了哪些推导/图表、使用哪些真实产物、命令与结果、身份/误差变化及未覆盖风险。
附正式文档、维护约定、检查报告和真实观察器入口的链接。
安装 skill、提交 Git 或推送按照本次授权执行，不由文档更新动作自动附带。
